# 握手、能力发现与通知

目标：用户提供的 HeyMelody / 欢律 17.6.5，SHA-256 `eacb314e092cfb6c2f075eee834498412255cadf184978f3dc16400f6e1dd5d4`。以下均为静态代码观察或对静态常量的推导；未连接 Enco Free4。

## 最小初始化

1. 建立 transport，BLE 时先完成 notify 订阅。
2. 发送命令 `0x0100`，payload 为空；用应用层序号匹配 `0x8100`。
3. `0x8100` payload 第 0 字节是状态；成功为 `0`。后续是能力位图，无单独的位图长度字段。每字节按低位到高位展开；APK 最多识别 69 位。
4. 每个能力位可以对应多个命令。完整表保存在 `capability-bits.json` 的 `table`；`table[i].commands` 就是第 i 位对应的命令集合。未知额外位保留原始数据。
5. 查询功能当前值；读取后决定展示哪些操作。
6. 如果需要实时状态，发送 `0x0200` 空 payload，解析 `0x8200` 为 `[status, eventCount, eventIds...]`。
7. 只订阅实际返回且实现了解析器的事件。如果位图声明支持 `0x0205`，发送 `[count,eventIds...]`；否则逐项发送 `0x0201` / `[eventId]`。

原 APK 成功收到能力后会发起较多初始化查询，不能由静态调用顺序证明其中每一条都是执行配置所必需。建议 SDK 采用上面的最小路径，真实固件如有额外前置条件再以抓包验证。

## 普通通知与 ACK

`0x0204` payload：`[eventId,eventData...]`。`0x8202`（读取注册事件）payload：`[status,eventId,eventData...]`。

建议最初只订阅这些事件与 `0x8200` 返回集合的交集：

| eventId | 含义 | `commands.i.b` 中是否发 ACK |
| --- | --- | --- |
| 01 | 电池 | 否 |
| 02 | 耳机状态 | 否 |
| 03 | 降噪 | 否 |
| 05 | 游戏 | 否 |
| 06 | 多设备连接信息 | 否 |
| 11（十六进制，十进制 17） | 提示音变化 | 否 |

不要对每条通知都发应答。`F2` 连接历史及 `F4` 诊断事件会调用 `commands.i.d`：回应命令 `receivedCmd | 0x8000`，复用收到的序号，payload 为 `[status,eventId,optionalExtra...]`。通用 API 未实现这些功能时可避免注册这两项。

证据：`init-response.json`（`ev_3dad35c8113a356f82bc2b3cbd99f97fcb1e617c3393671d9b2b8ffb8b695c15`）、`notification-dispatch.json`（`ev_aacaa37e3b9914b00fface318f9fa1b042d8fa685316ba0907a1cd839519be31`）、`notification-ack.json`（`ev_e9e8c7a6192f642018d7cf2bead6f5975b418debd08579dc83c8e77f7fdfe6e9`）。`notification-dispatch` Java 有重复块/类型推断告警，涉及复杂数据的部分应另用 smali 核对。

## 耳机主动请求主机

`HeadsetCoreService.m0` 区分命令类别：`cmd & 0x7F00` 为 `0100` 时交查询应答，`0200` 时交通知，`0500` 时交主机请求。它们不能混为一类。

已确认的例子：

| 收到 | 回应 | payload |
| --- | --- | --- |
| 0500（获取主机时间） | 8500，同 seq | `[0,unixSeconds LEu32]`；型号配置 `getUtcTimeZone` 启用时跟 `offsetSeconds LEi32`，共 9 字节 |
| 051C（获取 App 能力） | 851C，同 seq | `[0,fastDiscoveryFlag,0]`；Windows 自研客户端不应声明未实现的 fast discovery |

其他 05xx 包含手机空间模式、语音、账户同步等请求；这次未完整恢复这些服务。未知命令在 APK 的未分类分支会收到状态 `1`，但不要据此对所有已分类的 05xx 都自动回成功。

证据：`core-inbound.json` / `.smali`，`ev_3402a20187482a26ece27d10a6bc10b1b13cfa7b5575ffb0f9c8caa1c46755a0`。

## 实测边界

未证明 Enco Free4 当前固件会返回何种能力、BLE 连接是否允许与手机共存、是否主动发出 0500 / 051C，或是否需要额外握手。默认命令集合、位图和注册步骤均来自此 APK；最终兼容性仍需使用实际设备应答核对。
